# 系统架构

## 1. 架构概览

CreatorFlow 是单体 Next.js 应用。浏览器负责交互和流程编排，Route Handlers 负责数据校验、模型调用和媒体响应，SQLite 负责本地持久化。

```text
浏览器页面
  ├─ 项目列表 / 制作工作流
  ├─ 素材库
  └─ 模型配置
          │ fetch
          ▼
Next.js Route Handlers
  ├─ 项目与分镜
  ├─ 脚本 / 图片 / 配音
  ├─ 片头与背景音乐
  ├─ 模型配置与连接测试
  └─ 剪映草稿
       │                  │
       ▼                  ▼
本地 SQLite          外部 AI / 草稿服务
```

## 2. 页面职责

| 页面 | 职责 |
| --- | --- |
| `/` | 项目列表、项目元数据编辑、删除、批量生成 |
| `/create` | 四步制作工作流和草稿版本管理 |
| `/assets` | 片头、背景音乐上传与 Seedance 片头任务 |

## 3. 服务端模块

| 模块 | 职责 |
| --- | --- |
| `lib/types.ts` | 项目、分镜、素材和草稿版本类型 |
| `lib/projects.ts` | 项目、分镜和草稿版本持久化 |
| `lib/intros.ts` | 片头与背景音乐持久化、Seedance 状态 |
| `lib/model-config.ts` | 五类模型配置和 Key 保存 |
| `lib/script-prompt.ts` | 默认脚本提示词 |
| `lib/draft-prompt.ts` | 默认草稿提示词和旧提示词升级 |
| `lib/jianying.ts` | 草稿时间线、字幕、动画和外部调用 |
| `lib/media-duration.ts` | 读取上传或生成媒体的真实时长 |
| `lib/http-media.ts` | 支持 Range 的媒体响应 |

## 4. 数据表

| 数据表 | 主要内容 |
| --- | --- |
| `book_projects` | 书籍信息、提示词、素材关联和当前草稿 |
| `project_scenes` | 七段分镜、当前图片、图片版本和音频 |
| `project_videos` | 旧项目级片头或片尾视频 |
| `intro_templates` | 片头、背景音乐和 Seedance 任务 |
| `project_draft_versions` | 草稿链接和生成提示词历史 |
| `model_capability_settings` | 五项能力的服务配置和 API Key |

## 5. 关键数据流

### 脚本生成

页面输入 → 校验片头 → 读取多模态配置 → 调用模型 → 校验七段 JSON → 强制修正 s1/s2 → 重新分配时长 → 保存项目和分镜。

### 图片生成

分镜提示词 → 读取文生图配置 → 调用图片服务 → 必要时进行未成年人安全改写并重试 → 保存当前图片和版本列表。

### 配音生成

分镜口播和语速 → 调用语音服务 → 读取真实时长 → s0/s1 必要时提高语速重试 → 保存音频。

### 草稿生成

读取完整项目 → 校验 5 张图片和 7 条配音 → 读取媒体真实时长 → 创建 1080×1920 时间线 → 添加片头、图片、动画、标题、作者、字幕、旁白和背景音乐 → 保存草稿链接和版本。

## 6. 教学实现顺序的原因

- 页面骨架先确定信息结构，后续阶段只填充能力。
- SQLite 在模型调用前实现，使每个后续阶段都有稳定数据落点。
- 模型配置先于生成能力，避免在接口中硬编码凭据。
- 脚本决定图片和配音的数据结构，因此先于媒体阶段。
- 草稿依赖所有上游素材，必须最后实现。

## 7. 当前架构边界

- 单用户、单机数据库，无登录和权限。
- 长任务由浏览器请求串行驱动，无独立任务队列。
- 批量生成中断后不支持断点续跑。
- 媒体存储在 SQLite，适合本地 MVP，不等同于生产级对象存储。
- 剪映草稿依赖固定外部服务，不包含本地原生草稿格式适配器。
