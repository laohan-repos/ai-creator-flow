# CreatorFlow Design Spec

## 1. 设计目标

CreatorFlow 的界面是一套面向内容生产者的桌面工作台。视觉应当专业、轻量、可信，让用户把注意力放在制作步骤和素材状态上，而不是装饰元素上。

设计关键词：

- AI 工具感，但不过度使用霓虹和复杂渐变。
- 信息密度适中，适合连续处理多个分镜。
- 清晰表达等待、执行中、成功和失败。
- 以桌面工作流为主，同时保证窄屏可操作。

## 2. 品牌与视觉语言

### 2.1 品牌名称

- 中文产品名：书籍解说。
- 英文项目名：CreatorFlow。
- Logo：`public/brand/book-explainer-logo.png`。
- Logo 在侧边栏中使用 38×38 px，圆角 11 px。

### 2.2 基础设计变量

```css
:root {
  --purple: #6847f5;
  --purple-soft: #f1efff;
  --ink: #17182c;
  --muted: #7a8095;
  --line: #e5e7f0;
  --surface: #ffffff;
  --canvas: #f7f8fc;
  --danger: #d94b58;
  --success: #28885a;
  --shadow: 0 10px 34px rgba(43, 44, 78, 0.07);
}
```

| 用途 | 色值 | 使用位置 |
| --- | --- | --- |
| 主色 | `#6847f5` | 主按钮、当前步骤、链接、焦点 |
| 主色浅底 | `#f1efff` | 选中导航、编号、提示状态 |
| 主文字 | `#17182c` | 标题、关键内容 |
| 次文字 | `#7a8095` | 说明、时间、次级信息 |
| 页面背景 | `#f7f8fc` | 全局画布 |
| 卡片背景 | `#ffffff` | 面板和弹窗 |
| 分割线 | `#e5e7f0` | 卡片、输入框和列表边界 |
| 成功 | `#28885a` | 完成、连接成功、当前素材完整 |
| 错误 | `#d94b58` | 删除、失败、不可用素材 |

不要在同一页面新增另一套品牌主色。不同模型能力不使用不同大面积颜色，以状态和文字区分即可。

### 2.3 渐变

主操作按钮使用轻微紫色渐变：

```css
background: linear-gradient(135deg, #7756fa, #5b3ae9);
```

渐变仅用于主按钮、品牌图标背景和当前进度，不用于大面积页面背景。

## 3. 排版

### 3.1 字体

```css
font-family: Inter, ui-sans-serif, -apple-system, BlinkMacSystemFont,
  "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
```

提示词和结构化配置编辑器使用等宽字体：

```css
font-family: ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, monospace;
```

### 3.2 字号层级

| 层级 | 建议字号 | 用途 |
| --- | --- | --- |
| 页面主标题 | 22–28 px | 书籍解说、素材库 |
| 工作区标题 | 17–24 px | 当前书名、步骤标题 |
| 卡片标题 | 14–16 px | 分镜标题、弹窗标题 |
| 正文 | 13–15 px | 口播、主要说明 |
| 辅助文字 | 10–12 px | 状态、日期、提示 |
| Eyebrow | 10–12 px | 英文模块标识 |

主标题字重 700–800；正文避免全部加粗。中文正文行高建议 1.55–1.7。

## 4. 页面布局

### 4.1 桌面布局

- 页面最小高度为视口高度。
- 左侧导航固定，宽度 232 px。
- 页面内容为侧栏预留 262 px，右侧和顶部保留约 28–30 px。
- 主要内容宽度随视口展开，不设置狭窄文章式最大宽度。
- 页面背景为浅灰紫，所有主要内容放在白色面板中。

```css
.app-shell {
  min-height: 100vh;
  padding: 28px 30px 36px 262px;
}
```

### 4.2 侧边栏

- 固定在页面左侧，高度铺满。
- 白色半透明背景、1 px 右边框和轻微模糊。
- 品牌位于顶部，导航项纵向排列。
- 导航项高度约 42 px，圆角 9 px。
- 当前项使用浅紫渐变背景和紫色文字。
- Hover 不改变布局尺寸。

### 4.3 面板

```css
.panel {
  background: #fff;
  border: 1px solid #e5e7f0;
  border-radius: 12px;
  box-shadow: 0 10px 34px rgba(43, 44, 78, 0.07);
}
```

- 大工作区内嵌的小卡片可以取消阴影，仅保留边框。
- 相邻列表项使用 7–12 px 间距。
- 常规面板内边距为 16–24 px。

## 5. 页面结构

### 5.1 项目列表

页面头部左侧展示 Eyebrow、标题和说明，右侧展示“批量生成”和“新建书籍解说”。

项目行结构：

```text
[书名首字缩略图] [书名
                  作者 · 情绪] [日期] [编辑 删除] [打开]
```

- 缩略图 38×38 px，浅紫底、紫色字。
- 列表行白色或极浅灰底，Hover 时使用浅紫背景。
- 删除按钮使用危险色，不与主按钮同色。
- 无项目时使用虚线边框空状态，包含图标、标题和一句引导。

### 5.2 制作工作流

四步导航横向排列：脚本、图片、配音、剪映草稿。

- 步骤圆点 28–32 px。
- 未开始：灰色描边和浅灰背景。
- 当前：紫色渐变实心圆。
- 已完成：紫色或成功状态，并保持步骤可点击。
- 步骤间使用浅灰虚线连接。

步骤导航与内容面板在视觉上连接：导航面板下方圆角为 0，内容面板上方圆角为 0。

### 5.3 脚本分镜

- 每行包含分镜编号、标题和口播；s2–s6 额外提供图片提示词入口。
- 编号方块约 38×38 px。
- 桌面端口播保持单行摘要，空间不足时省略；窄屏允许换行。
- 页面头部展示当前书名、Hook、成功状态和总时长。

### 5.4 图片步骤

图片行结构：

```text
[118 px 预览] [分镜标题、状态、提示词摘要] [提示词] [生成/重新生成]
```

- 预览区域使用固定比例和 `object-fit: cover`。
- 无图片时使用浅紫占位和分镜编号。
- 生成中时整行增加紫色描边，不使用全屏阻塞。
- 点击图片进入编辑弹窗；大图查看使用深色全屏遮罩。

### 5.5 配音步骤

- 与图片行保持相同视觉节奏。
- 左侧分镜编号，中间口播和播放器，右侧修改与生成按钮。
- 播放器最大宽度约 420 px，不能挤压右侧操作。

### 5.6 素材库

- 顶部使用片头管理、背景音乐两个标签。
- 片头页并排展示“上传片头”和“Seedance 生成片头”。
- 背景音乐页只展示上传卡片。
- 素材以网格卡片展示预览、名称、来源、时长、默认状态和操作。
- queued/running/failed 使用明确状态面板代替空播放器。

### 5.7 剪映草稿

- 背景音乐选择单独使用面板。
- 草稿生成操作使用左右布局：左侧说明，右侧按钮和状态。
- 草稿版本使用纵向列表；当前版本以浅紫背景和紫色边框表示。
- “复制”是轻量文字操作，“设为当前”是次按钮，“移除”是危险弱按钮。

### 5.8 批量生成

设置弹窗宽度约 560 px；进入进度状态后扩展到约 760 px。

- 顶部展示完成数量和百分比。
- 进度条使用紫色渐变。
- 执行步骤使用圆形编号：等待为灰色、当前为紫色、完成为绿色、失败为红色。
- 任务队列桌面端两列，窄屏一列。

## 6. 组件规范

### 6.1 按钮

| 类型 | 样式 | 使用场景 |
| --- | --- | --- |
| 主按钮 | 紫色渐变、白字 | 生成、保存、确认 |
| 次按钮 | 白底、紫色边框 | 返回、取消、提示词 |
| 轻按钮 | 浅紫底、紫字 | 测试连接、管理素材 |
| 危险按钮 | 红色或浅红底 | 删除、移除 |

- 常规按钮圆角 7–9 px。
- 高度约 34–42 px。
- Disabled 降低透明度并使用等待光标。
- 同一操作区只保留一个主要按钮。

### 6.2 表单

- 输入框白底、1 px 灰色边框、8 px 圆角。
- 左右内边距约 12 px。
- Focus 使用紫色边框和 3 px 半透明焦点环。
- Label 位于输入框上方，字号约 12 px，字重 650。
- 帮助信息使用 10–11 px 次文字。
- 提示词输入区域使用较高 textarea，允许垂直缩放。

### 6.3 弹窗

- 遮罩：`rgba(18,19,37,.45)`，轻微背景模糊。
- 内容圆角 16 px，最大高度不超过视口减 48 px。
- 关闭按钮位于右上角，32×32 px 圆形。
- 弹窗出现使用轻微淡入、上移和缩放动画，约 180–220 ms。
- 点击遮罩可关闭非执行中弹窗；任务执行中不得误关闭。

### 6.4 状态提示

| 状态 | 文字色 | 背景 |
| --- | --- | --- |
| 工作中 | `#7655d8` | `#f3efff` |
| 成功 | `#28885a` | `#edf9f1` |
| 失败 | `#c44753` | `#fff0f1` |
| 普通提示 | `#5c48b9` | `#f1efff` |

状态提示应紧邻发生操作的区域，不仅依赖 Toast。错误中必须包含用户可采取的下一步。

## 7. 响应式规则

### 大于 1100 px

- 使用完整桌面布局。
- 脚本、图片和配音行保持多列结构。

### 901–1100 px

- 表单右侧说明区折叠。
- 复杂分镜行可以将设置区放到下一行。

### 621–900 px

- 侧栏缩为约 72 px，只展示 Logo 和导航图标。
- 主内容左侧间距缩至约 90 px。
- 步骤导航隐藏文字但保留步骤圆点。

### 620 px 及以下

- 侧栏变为页面顶部横向导航，高约 62 px。
- 当前导航项必须可见，其他导航可通过明确入口访问。
- 页面水平内边距约 12 px。
- 卡片、图片行、配音行和弹窗改为单列。
- 弹窗靠近屏幕底部，最大高度 88–90 vh。
- 操作按钮允许换行，但不得超出屏幕。

## 8. 交互规则

- 所有真实生成操作必须展示执行中状态。
- 生成期间按钮禁用，防止重复请求。
- 重新生成不得静默覆盖历史图片版本。
- 删除项目、素材和草稿版本必须二次确认。
- 模型 Key 保存成功后清空输入框，只显示配置状态。
- 用户切换步骤时不丢失当前内存中的修改。
- 生成草稿前保存最新页面状态。
- 操作失败后保留用户输入，方便修改后重试。

## 9. 可访问性

- 所有图标按钮必须提供 `aria-label`。
- 弹窗使用 `role="dialog"` 和 `aria-modal="true"`。
- 删除确认使用 `role="alertdialog"`。
- 执行状态使用 `role="status"`，不能只通过颜色表达。
- 图片 `alt` 包含分镜名称或用途。
- 输入框必须有关联 Label 或 `aria-label`。
- 键盘焦点必须可见。
- 正文和背景保持足够对比度。

## 10. Codex 实现要求

向 Codex 提交设计任务时应附加：

```text
界面必须遵守 docs/course/design-spec.md。
优先复用 CSS 变量和通用组件样式，不为每个页面重新发明颜色和按钮。
先完成信息层级和响应式布局，再添加轻量动效。
不得引入 UI 框架替换当前视觉语言。
```

设计验收重点：

- 三个页面品牌和导航一致。
- 主色、背景、卡片和状态色符合设计变量。
- 四步流程在桌面和窄屏都可理解。
- 列表、图片、配音和草稿版本的信息层级清晰。
- Loading、Success、Error、Empty、Disabled 五类状态均有明确表现。
- 390 px 宽度下无关键操作被截断。
