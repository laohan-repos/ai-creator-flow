# 阶段 04：书籍脚本生成

## 目标

接入多模态模型，生成并保存符合固定规则的 s0–s6 七段书籍解说脚本。

## 开始前

阅读：

- `AGENTS.md`
- `docs/CreatorFlow-需求文档.md` 第 7.2 节
- `docs/course/api-contracts.md` 第 2 节
- `docs/course/examples/sample-script.json`

## 需求

1. 用户可填写书名；留空时模型自动选书。
2. 用户必须选择真实片头，时长不得小于 2.3 秒。
3. 背景音乐可选，但 ID 必须指向背景音乐素材。
4. 默认提示词必须使用 `{{bookTitle}}` 变量，页面允许修改和恢复默认。
5. 自动选书时把已有项目书名加入黑名单，并明确禁止简称、别名和副标题形式的重复。
6. 使用多模态能力的 Base URL、模型和 Key 调用 Chat Completions 兼容接口。
7. 清除模型输出中可能存在的 `<think>...</think>` 后解析 JSON。
8. 输出必须正好七段；每段口播非空；s2–s6 图片提示词非空。
9. 服务端强制修正 s0–s2：
   - s0 为开场钩子。
   - s1 逐字为“今天我们分享的是”，语速 1.2，图片提示词为空。
   - s2 为“《当前书名》。”，并具有书籍核心主视觉提示词。
10. s0、s1 时长总和必须等于片头真实时长。
11. 整体按约 26 秒重新分配 s3–s6 时长。
12. 成功结果立即保存为新项目，页面进入图片步骤。

## 错误处理

- 未选择片头或片头过短：400。
- 模型配置缺失：412。
- 外部请求失败、JSON 错误、分镜数量错误：502。
- 不得在失败时生成占位项目。

## 不做

- 不调用图片或语音模型。
- 不自动生成媒体占位内容。
- 不依赖客户端保证固定口播，服务端必须校验和修正。

## 验收

- 指定书名和自动选书均能提交。
- 返回正好七段且结构符合示例。
- s1、s2 固定口播无法被模型覆盖。
- s0、s1 时间预算正确。
- 项目刷新后仍可读取。
- 错误模型输出不会被保存。
- `npm run build` 通过。

## 发给 Codex

```text
请阅读 AGENTS.md、阶段 04、产品需求 7.2、API 契约第 2 节和示例 JSON。
先检查现有项目、素材和模型配置实现，只完成真实脚本生成。
固定七段规则必须由服务端执行，失败时不得返回演示数据。
实现后运行 npm run build，并逐项报告七段结构、时长和错误处理验收。
```
