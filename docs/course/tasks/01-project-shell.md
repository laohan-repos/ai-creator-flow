# 阶段 01：项目骨架与页面

## 目标

基于 Starter 项目建立 CreatorFlow 的页面结构、导航和四步工作流静态状态。本阶段不连接数据库和模型。

## 开始前

阅读：

- `AGENTS.md`
- `docs/CreatorFlow-需求文档.md` 第 2、5、6 节
- `docs/course/architecture.md` 第 1、2 节
- `docs/course/design-spec.md`

## 需求

1. 建立统一的左侧导航，包含“书籍解说”“素材库”“模型”。
2. `/` 展示项目列表标题、项目数量、空状态、“新建书籍解说”和“批量生成”入口。
3. `/create` 展示四步导航：脚本、图片、配音、剪映草稿。
4. `/create` 第一阶段展示书名输入、片头选择占位、背景音乐选择占位和生成按钮。
5. `/assets` 展示片头管理和背景音乐两个标签，以及上传区域和空状态。
6. 使用共享 CSS 建立清晰的桌面布局和基本窄屏适配。
7. 所有按钮在本阶段只允许展示明确的“功能将在后续阶段实现”提示，不得伪造成功结果。
8. 颜色、排版、按钮、面板、步骤导航和响应式行为遵守 Design Spec。

## 不做

- 不创建 API Route。
- 不创建 SQLite 数据库。
- 不调用任何模型。
- 不实现真实上传和批量生成。

## 建议步骤

1. 先检查 Starter 现有文件。
2. 提取统一导航或至少保证三个页面结构一致。
3. 完成页面静态结构。
4. 添加空状态和可访问性标签。
5. 运行构建并检查三条路由。

## 验收

- `/`、`/create`、`/assets` 均可直接访问。
- 当前导航项视觉状态正确。
- 四步名称和顺序正确。
- 无数据时页面不出现运行时错误。
- `npm run build` 通过。

## 发给 Codex

```text
请先阅读 AGENTS.md 和 docs/course/tasks/01-project-shell.md，再检查当前仓库。
只实现阶段 01，不创建数据库、API 或模拟生成结果。
完成后运行 npm run build，并按本任务验收项报告。
```
